# X/Twitter 动态监控与钉钉通知控制台（非官方）

一个在本机运行的 X/Twitter 动态监控工具：通过浏览器页面轮询或官方 X API 获取指定账号的内容，整理为钉钉 Markdown 通知，并在控制台查看运行日志和最近推送记录。

项目使用 **React + Vite + Express + Playwright Core**。主要使用方式是 Windows 上的本地浏览器控制台，不需要先构建桌面 EXE。

本项目不属于 X/Twitter 或钉钉官方产品，不保证第三方页面、接口及通知服务持续可用。请仅处理你有权访问和转发的内容。

## 功能概览

- 两种数据源：本机 Chrome/Edge 页面轮询，以及官方 X API 的 Recent Search / Filtered Stream。
- 浏览器模式尝试扫描账号的帖子、回复和页面可见的订阅入口。
- 目标作者匹配、转推/原创筛选和基于推文 ID 的去重。
- 钉钉 Markdown 通知，可选加签；浏览器模式尝试补充详情正文、图片链接及引用内容。
- 可选中文机器翻译，默认开启，原文与译文分别发送。
- 正文或引用内容命中 A 股代码格式时，额外发送一条提醒；这只是文本规则匹配，不验证证券是否存在，也不提供投资分析。
- SSE 更新控制台日志和状态，保存最近 200 条捕获/推送记录及最多 20,000 个去重 ID。

## 两种模式的区别

| 项目 | 浏览器模式 | 官方 X API 模式 |
| --- | --- | --- |
| 准备条件 | 本机安装 Chrome/Edge，按需手动登录 X | 自行提供有相应权限的 Bearer Token |
| 获取方式 | 读取实际浏览器页面 | Recent Search 轮询或 Filtered Stream |
| 费用与权限 | 不使用 X API Token，不代表所有内容免费或可访问 | 由 X 的接口权限、额度和计费规则决定 |
| 获取范围 | 每个账号、每个频道最多取 5 条已加载页面结果 | Recent Search 每次最多 10 条，没有分页补全 |
| 首次只建基线 | 已实现：账号首次扫描时标记已有内容而不推送 | 当前没有实现这一基线逻辑 |
| 详情增强 | 尝试读取全文、引用和图片；失败可能回退摘要 | 当前主要处理文本、作者和发布时间 |

“订阅”仅指页面向当前登录账号展示且允许访问的入口，不会绕过订阅或访问权限。页面结构、登录状态和加载速度变化都可能导致识别失败。作者匹配也不是 X 官方认证或内容真实性验证。

## 环境要求

- **Windows 为主要使用路径。** 其他系统及完整桌面发行包尚未验证。
- **Node.js 24 和 npm**。本次发布准备使用 Node.js 24 检查源码与构建；下面的安装命令需要另外确保 npm 可用。
- 浏览器模式需要已安装的 **Google Chrome 或 Microsoft Edge**。项目使用 `playwright-core`，不会自动附带一个完整浏览器。
- 能访问所选数据源、钉钉以及按需使用的翻译服务的网络环境。

## 快速开始

下载源码后，在**项目根目录**打开 PowerShell：

```powershell
node --version
npm --version
npm ci
npm run dev
```

默认控制台地址为：

```text
http://127.0.0.1:3007
```

启动时会尝试自动打开控制台窗口。如果没有打开，可手动在浏览器访问上述地址。`npm ci` 需要下载依赖，当前锁文件使用 npmmirror 公共镜像下载地址；若 PowerShell 阻止运行 `npm.ps1`，可在同一终端使用 `npm.cmd ci`、`npm.cmd run dev`，不必更改全局执行策略。

如不希望启动服务时自动打开控制台：

```powershell
$env:X_MONITOR_NO_AUTO_OPEN="1"
npm run dev
```

**启动服务不会自动开始监控 X。** 不过，它会创建本地 `data` 目录、读取已有记录并写入去重数据。

### 首次配置

发布版不包含真实监控账号、Token、钉钉 Webhook、加签密钥或浏览器登录态；这些内容需自行填写。

1. 在控制台选择数据源，首次可使用浏览器模式。
2. 填写有权使用的钉钉机器人 Webhook；机器人启用了加签时，再填写对应 Secret。
3. 填写监控账号用户名，可每行一个，也支持 `@用户名` 或 X/Twitter 主页链接。
4. 保存配置。浏览器模式点击 **打开/登录 X**，在弹出的独立浏览器窗口中手动登录。
5. 按需选择频道、筛选、翻译和轮询间隔，再点击 **启动监控**。

默认轮询间隔为 60 秒，最小值为 20 秒。每轮按账号和频道依次处理，实际周期包含抓取、翻译、发送耗时以及轮询等待时间，不是严格每 60 秒完成一次，也不保证实时或不漏推。

**修改配置后，应停止监控再重新启动。** 已开始的循环使用启动时的配置，不保证实时应用所有修改。

### 会产生真实操作的按钮

- **打开/登录 X**：启动实际浏览器并访问 X，登录态会保存在本地独立配置目录。
- **测试钉钉**：向所填机器人对应的群发送真实测试消息，不是离线检查。
- **同步最近**：真实获取内容，并可能立即发送通知，不是只读预览。
- **重置去重**：清除当前去重/基线状态，可能使后续同步重复发送已有内容。
- **停止监控**：停止后续循环，但不保证取消正在进行的页面加载、翻译或通知发送；短时间内仍可能有操作完成。

默认浏览器模式开启“首次只建基线”，首次识别到的已有内容不会发送。官方 API 模式没有同等基线保护，首次运行 Recent Search 可能发送返回的已有内容。

## 可选的环境变量配置

通常可直接在控制台设置。若偏好环境变量，可在根目录将 `.env.example` 复制为 `.env`，再填入自己的值：

```powershell
Copy-Item .env.example .env
```

| 变量 | 用途 |
| --- | --- |
| `TWITTER_PROVIDER` | `browser` 或 `x-api`，默认使用浏览器模式 |
| `TWITTER_USERS` | 待监控用户名列表 |
| `X_BEARER_TOKEN` | 仅官方 X API 模式需要 |
| `DINGTALK_WEBHOOK` | 钉钉机器人地址 |
| `DINGTALK_SECRET` | 可选加签密钥 |
| `PORT` | 本地控制台端口，默认 `3007` |
| `X_MONITOR_NO_AUTO_OPEN` | 设置为 `1` 禁止服务启动时自动打开控制台 |
| `CHROME_PATH` / `MSEDGE_PATH` | 自定义浏览器可执行文件候选路径；程序仍会先尝试标准 Chrome/Edge channel |
| `NODE_ENV` | 显式设为 `production` 时提供构建后的前端 |

注意：

- 已保存的 `data/config.json` 中的非空配置通常优先于环境变量。
- 控制台中的凭据输入留空表示保留已有值，**不是删除凭据**。
- 保存配置可能将环境变量中的凭据一起写入 `data/config.json`。
- 请从项目根目录运行；`.env` 和 `data` 的位置依赖当前工作目录。

## 构建并运行生产前端

```powershell
npm ci
npm run build
$env:NODE_ENV="production"
npm start
```

`npm run build` 生成 `dist`，不是生成 Windows EXE。在仍保留源码 `index.html` 的目录里，应显式设置 `NODE_ENV=production`，不能认为执行过 build 后 `npm start` 就一定切换到生产模式。

需要恢复开发模式时，可在新的 PowerShell 窗口执行 `npm run dev`，或先移除当前会话的 `NODE_ENV` 设置。

## 数据、隐私和安全边界

- `.env` 和 `data/config.json` 中的 Token、Webhook、Secret 都是**本机明文配置**，不是加密保险箱。
- `data/browser-profile-chrome` 等浏览器配置目录包含 Cookie 和登录态；`data/records.json` 包含抓取正文、链接和通知结果。不要公开整个 `data` 目录。
- 中文翻译默认开启，会把正文发送给 `translate.googleapis.com`。可在控制台关闭“自动中文翻译”；本项目不是全本地处理工具，也不保证该第三方端点的持续可用性。
- 钉钉通知会把相关内容发送到对应群；订阅内容、个人信息和其他受限内容不应在无权限时转发。
- 当前控制台**没有登录认证**，部分配置接口会向本地页面返回钉钉 Webhook 和 Secret。保持服务仅监听 `127.0.0.1`，不要改为公网监听，也不要用端口映射或隧道将它直接公开。
- `.gitignore` 不能代替脱敏，不能阻止网页手动上传，也不能自动清除已经提交过的内容。发布前检查配置、日志、截图、历史压缩包和构建产物；凭据一旦泄露，应更换而不是仅删除当前文件。

## 已知限制

- 页面选择器、文本规则和第三方接口可能变化，不能保证内容完整、全文识别或持续兼容。
- 浏览器仅扫描有限的已加载结果，Recent Search 仅获取一页。高频账号、较长离线时间或扫描失败都可能导致遗漏；当前不是完整历史归档或补全工具。
- 去重 ID 在发送前记录。**发送失败不会自动重投**，不能将去重理解为可靠消息队列。
- 原文发送成功，不代表翻译或 A 股代码额外提醒也发送成功，应分别查看状态。
- 官方 Filtered Stream 启动会在远端删除带有本工具标记的旧规则，再创建新规则；使用同一 X 应用的多个实例可能相互影响。该操作不是纯读取。
- 关闭控制台页面不等于停止 Node 后台进程。源码运行时可先在界面停止监控，再到启动服务的终端按 `Ctrl+C` 结束服务。
- 提供源码和操作步骤不代表已验证真实 X 查询、钉钉发送、订阅内容、翻译服务或跨电脑桌面发行包。

## 可选：Windows 桌面壳源码

`desktop-shell` 提供 WinForms + WebView2 壳，目标为 `.NET Framework 4.7.2`；`launcher` 则包含另一种浏览器窗口启动器源码。它们不是日常使用的必要步骤。

若要自行研究构建，可在准备好 Windows 构建环境、合适的 .NET SDK 和 .NET Framework targeting pack 后，从以下命令开始：

```powershell
dotnet build desktop-shell/XMonitorDesktop.csproj -c Release
```

这只构建桌面壳，**不会自动组装完整发行包**。运行还需要 WebView2 Runtime，以及壳预期的 `app`、`runtime/node.exe` 和应用依赖目录。源码没有完整的一键发行包组装流程；桌面壳还固定使用 `3007` 端口。

壳启动的 Node 进程不会因关闭壳窗口而自动退出。不要把单个编译得到的 EXE 当作可独立分发的完整程序，也不要在发行包中放入自己使用过的 `data`、`.env` 或登录态。
